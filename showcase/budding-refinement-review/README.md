# Budding entrance refinement review

Owner request, 2026-10-22: separate the mother and text chamber a little farther, narrow their connection, add room to the right of the label and make the glass look less flat. The latest R3 correction explicitly allows color from the accepted large form’s blue/violet environment and asks for its full round mother and clean, soft chamber lighting. This supersedes the earlier no-colored-layer experiment. This isolated review compares the unchanged production BuddingLink with one proposed contour and material. It does not change the homepage dependency or library defaults.

Run `npm run dev` and open `/showcase/budding-refinement-review/index.html`. The Vite multi-page build includes this entry. Hosted review target: `https://alvenx.com/ui/budding-refinement-review-20261022/`.

- `geometry.ts` reuses the accepted volume coverage samples and reconstructs a periodic uniform cubic B-spline, retaining C2 joins. At full growth the chamber moves approximately 0.24 mother diameters farther right, and its right contour receives up to 0.12 diameters extra room. The round mother is protected: sample positions at x <= 330 receive neither horizontal separation nor neck compression. The lighter 14% local neck construction is centred at x=410 with a 60 logical-pixel Gaussian scale and a smooth gate from x=330 to375. This is a construction parameter, not a claim of an exact 14% reduction in the final spline's minimum thickness.
- `main.tsx` preserves the existing LiquidControl optical body and derives its clip, refraction normal map, rim and hit path from that contour. The real-backdrop glass remains underneath a transparent reference-material layer. The proposal's label has an additional 0.16-diameter right inset.
- `reference-volume.ts` adapts the actual fragment shader from `src/volume-renderer.js` using Vite’s raw-source import; it extracts the shader literal without evaluating JavaScript. The accepted continuous `interiorPotential`/`heightAt`, finite-difference normals, blue/violet environment, refraction approximation and broad softbox reflection remain the source of the visible material. Checked interface hooks add the same inverse contour-coordinate mapping, local bounds and transparent output. Changed upstream shader interfaces fail explicitly rather than silently selecting a different model. The layer has up to 0.84 coverage alpha, then the existing 0.82 CSS opacity; it is an environment approximation over real backdrop optics, not a claim that the analytic environment is the real page or that both layers are physically unified. The R2 neutral-heightfield shader is removed from the active review and retained only in historical evidence.
- The WebGL context and shader are prepared as the pearl approaches the viewport (160 px visibility margin), before first activation. A fixed 1.5x CSS-resolution raster is independent of device pixel ratio: 295 x132 = 38,940 pixels for the 54 px proposal. Growth never resizes the canvas, no PNG encoding is used, and identical paths/materials keep the retained result. Drawing follows the existing contour/clock callback, with no additional animation loop; the resting component sleeps. Context/program/buffer/shaders are disposed on unmount or disabling the material layer. This is a bound for this isolated proposal, not evidence of GPU completion latency, physical phone power use or whole-page frame rate. A renderer failure leaves the original actual-backdrop control available.
- `review.css` supplies the comparison layout and a homepage-like blue/violet environment. Both examples use the real 54 px mother size; the proposed expanded occupied width is about 194 px versus 175 px. Actual occupied width moves the adjacent GitHub link.

Activate each empty mother with pointer, touch or Enter/Space, then use the revealed native link. Reset restores both examples. The lighting toggle isolates the volume cue. Reduced motion reveals the final state immediately. Review screenshots and browser checks are retained with the navigation-unification publication records; desktop browser testing does not certify physical iOS/Combo Touch behavior or mobile power use. Owner visual acceptance precedes any change to the production homepage.
