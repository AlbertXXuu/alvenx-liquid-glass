Before JavaScript, the visible circle is a genuine native destination link. Modified/non-primary clicks retain native link behavior. A mouse, touch or Space press begun before hydration and released after replacement is handed to the live action without losing the first gesture. Cancellation/outside release does not activate it. With no JavaScript or a failed main module, the real destination link remains useful; it does not pretend the physics engine is ready. After enhancement there is only one focusable action on the mother, and focus transfers without scrolling.

`reference-volume.ts` starts compilation near visibility and feature-detects `KHR_parallel_shader_compile`. Its existing shared clock polls only completion while preparation is pending. Link status, attribute/uniform reflection, buffer/texture setup and draw are deferred until completion succeeds. The poll stops after completion, context loss, failure, unmount, or ten seconds of foreground shared-clock preparation time while still incomplete. Hidden wall time does not consume this budget; completion is checked before the deadline so an already completed program remains usable on return. There is no new continuous animation loop. Without the extension, the accepted material is still prepared after an observed first paint (or two shared-clock paint opportunities where the paint API is unavailable); a synchronous compiler wait can remain on that path. [The Khronos specification](https://registry.khronos.org/webgl/extensions/KHR_parallel_shader_compile/) explicitly distinguishes nonblocking completion polling from the potentially blocking fallback. [MDN WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices#prefer_khr_parallel_shader_compile) recommends this extension. The [MDN compatibility data](https://raw.githubusercontent.com/mdn/browser-compat-data/main/api/KHR_parallel_shader_compile.json), checked on 2026-10-22, records Chrome 76+, Safari 14.1 and mirrored iOS support, with Firefox unsupported; the actual runtime probe remains authoritative for a device/driver.

The closed poster is removed only when a matching live draw is committed. If the visitor activates while compilation is still pending, the unchanged current C2 native-backdrop optics respond immediately, but the extra blue-violet volume is temporarily flatter. It blends in over 160 ms once the matching live material is ready. The forced-pending screenshots deliberately retain this visible limitation. No growth-zero image is stretched across the growing body. The existing one-frame physics/optical scheduling is preserved to keep the host dimensions, path, native label and material coherent; R6 does not claim a new zero-frame response.

“First visible accepted frame,” “live material ready,” “queued activation before the main module,” and “input-to-growth after readiness” are separate measurements. Network transfer, module download, browser paint and GPU compilation still take time. This implementation does not promise literal zero latency, stable FPS, or physical iPhone/iPad/Safari/Combo Touch acceptance.

## Accepted shape and material contract

Owner correction, 2026-10-22: the R4 content chamber looked too rectangular, with nearly vertical sides. R5 changes its terminal superellipse exponent from 3.2 to 2.2, giving both sides a continuous outward curve while preserving the measured width, height, native text, optical spacing, round mother, independent hover and return behavior. The joined morph and terminal shader use this same target exponent. R4's profile/committed-path material correction remains in place. The current homepage component and library defaults remain unchanged; immutable R4 and earlier source tags retain their historical results.

Run npm run dev and open /showcase/budding-refinement-review/index.html. The Vite multi-page build includes this entry. The parent publication task owns the final hosted namespace and stable review URL.

- geometry.ts preserves the accepted coverage kernel and reconstructs periodic cubic B-splines. At 54 px, separation is now 0.50D = 27 px, with the final chamber fitted to the measured native label and approximately 0.22 chamber heights of space on both sides. The full final chamber, including added contour room, is the content slot. The previous one-sided 0.16D inset is removed; only a 0.2 px correction for the label ink offset remains. At 54 px the measured advance is 82.835 px, so the final chamber is about 116.10 px wide with roughly 17 px ink space on each side. Real occupied width grows from 66 px to about 212.1 px, moving GitHub in layout. The round mother is protected during the early joined phase; the R3 gentle 14% local neck construction remains before the terminal morph.
- Between growth 0.70 and 0.95, the connector smoothly narrows while the lobes approach a round mother and a clean superelliptic chamber. At growth 0.95 the almost invisible bridge changes to two independent closed C2 contours. Each component retains C2 joins; the topology-changing instant is explicitly not claimed to be one globally C2 surface. On return the same geometry parameter reverses, rejoins and settles as the mother.
- The R5 chamber exponent is exported once from geometry.ts and reused by the terminal shader. Its value 2.2 is close to an ellipse (2), preserving a little more content area while avoiding the broad, almost vertical shoulders produced by 3.2. At one quarter of the chamber height away from its centre, the boundary bows inward substantially more than R4. This curvature change does not widen the native text slot or alter its optical inset.
- main.tsx preserves position and velocity when the target reverses using a critically damped update on the existing shared clock. Re-clicking the mother during return reopens continuously. A pointer-down on either visible shape or its native destination link stays inside. A pointer-down in the transparent gap or on the surrounding background starts return. The handler tests the current visible Path2D once per pointer-down, rather than treating the whole host rectangle as filled. No mouseleave or arbitrary dismissal timer is used. Escape closes while focus is inside. Scrolling the host completely out of view settles the hidden state to the mother without offscreen animation work; returning to view starts closed.
- After separation each lobe has independent smoothed proximity, press and pointer offsets and deforms around its own centre. Its proximity radius is bounded by half the transparent gap (and at most 28 px), so facing-edge hover cannot activate the other object, including the narrow 44 px case. Hovering or pressing the right chamber does not transform the left mother, and vice versa. The native label slot follows only the right chamber's position and size while its font remains unscaled; its optical margins therefore remain balanced during hover. The reference shader uses matching per-lobe inverse transforms before evaluating the accepted height and material. This uses the existing clock, with revision checks and sleeping local motion, not a second animation loop.

The comparison's production baseline remains the unchanged original component. Checked interface hooks add small-control coordinates, the contour mapping, terminal independent dome potentials and transparent output. An eight-entry path/frame cache and a MutationObserver on the committed rim SVG submit the matching material and contact shadow only after that path is displayed; material-only updates may reuse the currently matching path immediately. The small fixed 1.5x CSS raster is independent of DPR, retains its result at rest, does not resize during growth and uses no PNG encoding. The existing clock owns active updates; no additional animation loop is added. Buffer/program/shaders are disposed when the material turns off or the component unmounts. CPU submission timing is not GPU completion time or a frame-rate guarantee. If the added renderer is unavailable, the actual-backdrop control remains available.
