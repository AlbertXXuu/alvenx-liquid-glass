# 运行时、性能与宿主契约（1.1.1）

用户于 2026-10-16 明确后续从本库获取组件重新开发，不接已有主页。本轮在保持 v6 轮廓、端部关系、材质参数及 DOM 文字的基础上，处理调度、法线工作区、画布预算和兼容渲染；冻结目录没有改写。视觉基线确认不等于所有降级渲染、设备和新产品的视觉验收。

## 可见性与活动调度

共享 `GlassClock` 以浏览器 requestAnimationFrame 配合累计时间相位驱动物理过程，默认预算 60 次/秒。移除旧固定 15ms 门槛：75Hz 显示环境不会因此直接降成 37.5Hz，144Hz 也不必运行 144 次昂贵计算。`useGlassSettings({ maxFps: 90 })` 或 `new GlassClock({ maxFps: 90 })` 可明确调整 1–240 次/秒预算；无效值使用 60。它是工作频率上限，不承诺达到该呈现帧率。时间步最长 34ms，防止长停顿后物理过程跳变。document 隐藏时取消动画；没有持续任务时不请求下一帧。高刷新率回归使用合成时间戳，不冒充物理显示器测试。

`LiquidControl` 保留静止外观和已生成图像。仅在尺寸、设置、指针、焦点、按压、位置或尚未收敛的形变需要时计算下一帧。背景动画不再迫使全部静止控件每帧测量布局。IntersectionObserver 检测屏幕外控件／形体并暂停计算；观察器缺失时保守继续工作。CSS／SVG 的浏览器合成成本仍然存在，暂停 JS 不等于 GPU 零成本。

大形体在屏幕外暂停环境、形变和出芽；返回时继续暂停前进度，不追赶离屏期间的时间。系统减少动效优先于用户开关。隐藏标签页和屏幕外是不同路径，均需回归。持续保持同一轮廓、clip、边缘与命中，不为省计算量化指针输入。

滚动／窗口 resize 自动使位置缓存失效。宿主通过布局、CSS transform 或列表重排移动一个控件，且没有 resize／scroll 时，需在布局完成后调用 `clock.invalidateLayout()`；自定义被拖动的控件也可使用 `interaction.position` 传入变更 token。内置 slider／switch 和展示透镜已处理此路径。例如：

```tsx
useLayoutEffect(() => { clock.invalidateLayout(); }, [clock, sidebarOpen]);
```

每个场景复用一个 clock，卸载时释放订阅。不要为了每个按钮启动额外 RAF 循环。

## 法线与缓存

法线计算仍同步执行，R/G 位移算法与冻结基线保持逐像素一致。所有实例共用三个 Float32 工作缓冲区、一个不到 4KB 的 Float64 列和缓冲区，以及两张工作画布，先计算宽核，再复用原始缓冲区计算窄核；已完成的图像是独立字符串，不暴露可变工作缓冲区。工作区尺寸由法线图上限与核 padding 限制，不随控件数量累计。

跨实例精确输入缓存最多 48 项、估算 2 MiB，包含输入 key 和 data URL 的保守 UTF-16 字节估算；不量化几何。相同输入命中缓存后不重复读回、计算或 PNG 编码。每个已挂载实例还保留当前结果，浏览器也会缓存 SVG 和图像；缓存上限不等于整个页面内存上限。

小控件使用 `channels: 'rg'` 跳过未使用的 B 通道镜面运算；通用函数默认 RGB。DOM 边缘光照走原有独立轮廓。保留浏览器原生同步 PNG 编码，避免引入异步图像替换延迟；当前优化是减少编码次数，不宣称移除了所有编码成本。最后一个光学实例销毁时释放工作区和共享缓存，重复销毁安全。

`scripts/qa-optics.cjs` 包含冻结 RGB 对比、R/G/alpha 对比、跨实例复用、缓存预算和释放检查。32 个相同 64×44 透镜的定向检查只需一次 PNG 编码和约 2.17 MiB Float32 工作区；旧实现同样 32 透镜仅 Float32 缓冲区约 92.38 MiB。这是指定尺寸的工作缓冲区比较，不是整个页面 RAM 或 GPU 显存比较。

## 大画布预算

`VolumeStage` 支持 `renderBudget={{ maxPixels: 2_000_000, maxDpr: 2 }}`。默认最多 200 万像素、DPR 最高 2；设备提示为内存不超过 4 GiB、逻辑处理器不超过 4，或 saveData 开启时，默认改为 100 万。提示缺失则用普通预算；这些是保守策略，不是 GPU 性能检测。硬件纹理／视口尺寸上限同样生效。无效、非有限或非正预算回到安全默认。

预算限制的是 canvas 后备缓冲区，1000×560 逻辑几何、鼠标坐标和 DOM 正文保持原有尺寸。CSS 像素模糊语义按实际栅格比例换算。`data-render-pixels`、`data-pixel-budget`、`data-render-scale` 可用于宿主诊断。高 DPR 下画布可能不按物理像素一一渲染，这是显式的质量／性能折中；文字不随其降采样。

预算不是自动帧率保证；新宿主可在实际 profiling 后明确覆盖。不存在根据短暂帧率抖动不断升降画质的循环。WebGL 不可用或上下文丢失时保留同一静止解析轮廓的蓝紫珠光 SVG 插画，标明静态替代，输入及动作继续工作；恢复后重新调度。它不具有同等动态体积光照。

## 验证口径

基础入口：`npm run check`、`npm run build`、`npm run test:contract`、`npm run test:runtime`。浏览器脚本：`scripts/showcase-qa.cjs`、`scripts/qa-optics.cjs`、`scripts/compatibility-qa.cjs`。兼容模式及物理 Safari／iOS 的边界见 [compatibility.md](compatibility.md)。安装验证必须使用本版 tgz，在仓库外新建消费项目，不能由上层 node_modules 掩盖缺失依赖。

性能复测使用正式构建、相同视口和操作，记录设备、引擎、采样时间、主线程占用、画布提交次数、布局读取和缓冲区存储。画布提交频率不等于最终呈现 FPS；GPU 进程 CPU 不等于 GPU 利用率；短测不证明无泄漏、续航或长期稳定性。浏览器私有提交内存包含运行时和缓存，不当作组件独占物理内存。旧 1.0.0 证据保留，只能作为对照。

持续悬停仍是计算热点，CPU 并未在所有场景下降。共享工作区主要改善实例扩张时的内存，调度主要改善空闲／离屏工作；保持约 60 次绘制不等于已经满足大型业务页面的主线程预算。DPR2 本轮为 1,997,952 像素，提交约 60 次/秒；实际显存、GPU 利用率、续航、热限制和低端设备未测。整个独立测试 Chrome 进程组本轮默认私有提交约 341 MiB，空白基线约 294 MiB；这不是组件独占内存，也不据此推算通用节省百分比。

中途曾试过直接跟随浏览器每个 RAF，实测默认画布约 150 次/秒、持续悬停主线程约 77%；该方案已被替换为本版相位补偿 60Hz 默认预算，不作为交付模式。

## 2026-10-17 持续悬停优化（1.1.0 → 1.1.1）

本轮不更改已确认的轮廓、法线分辨率、模糊核、高光、折射参数、60Hz 更新预算、完整精度指针输入或弹簧时间常数。水平计算分离边界和内部；垂直计算按连续内存顺序访问，使用 Float64 列和保持原 JS number 累加顺序。每轮卷积按非零 alpha 支持区扩展，跳过可证明为零的填充；若滑动和留下非零浮点消减残差，则精确保留其尾部并扩展下一轮范围。覆盖整个栅格时走完整遍历，最后实例销毁时释放列和。另移除一个已无引用的 SVG clipPath 定义，实际 backdrop／hit 的 CSS path 与边缘路径保持同源。

同一 Windows／i9-14900HX／RTX 4060 Laptop、Chrome 155 正式构建，1364×1100、DPR1，旧版与新版按 A–B–B–A–A–B 顺序交替运行。每次约 6 秒，提交相同 180 个控件相对坐标；下表是各三次的中位数。不是随机统计实验，不能推断所有设备的固定收益。

| 指标 | 1.1.0 | 1.1.1 |
| --- | ---: | ---: |
| 持续悬停：主线程忙碌比例 | 57.64% | 54.96% |
| 持续悬停：脚本执行时间比例 | 32.75% | 25.47% |
| 持续悬停：画布提交／秒 | 59.66 | 59.48 |
| 持续悬停：提交间隔 p95 | 26.90ms | 26.90ms |
| 唯一 RG 图计算微基准中位数 | 5.2ms | 2.4ms |

主线程总忙碌时间下降约 2.68 个百分点（相对约 4.65%），脚本执行时间相对下降约 22.25%；不能把法线计算约 53.8% 的微基准收益说成整个 UI 的收益。单次普通滑条试验为 19.29% → 17.06%，仅为一对短测，不作为普遍降幅保证。画布提交不是呈现 FPS；持续悬停仍是较重的场景。原始三次主线程样本：旧版 62.03／57.64／56.96%，新版 54.96／55.14／54.15%。

质量证据：52 种形体分别 RGB／RG 解码像素与尺寸对照，加释放检查共 209 项通过；1,000 组稀疏、极端指数与大核 Float32 数组精确对照通过。一个卡片的静止／悬停／按住三个稳定状态，固定背景时间 0 和相同指针坐标后，每幅 35,600 像素裁剪的最大／平均／RMS 差值均为 0。该截图证据限定当前 Chrome、DPR1 和这三个稳定状态，不扩大为全部过渡帧／浏览器认证。

独立交互回归检查了 18/18 个不同拖动值、滑条与开关的保持越界、释放、回弹中重抓、中点状态切换、键盘中间态、减少动效及 390px 布局。渲染时间仍可能受机器负载影响；这些检查不替代物理触控或主观舒适度验收。

无压缩 PNG 实验没有进入运行时：虽然同步编码更快，代表性 URI 体积达到原来的 5.53 倍，真实 SVG feImage／位移滤镜实验端到端中位耗时 2.10ms → 2.80ms。保留现有原生 PNG 压缩，未以更大资源、异步图像延迟或降低画质换取一个局部编码数字。

完整源码的 `docs/validation/hover-1.1.1/` 保留微基准、像素对比、质量回归和正式构建原始数据；[便携对比页](hover-comparison.html)内嵌实际截图。`scripts/qa-optics-speed.cjs` 使用随包 1.1.0 夹具，`scripts/hover-quality-qa.cjs` 检查交互，`scripts/hover-benchmark.cjs` 记录固定轨迹。1.0.0 与 1.1.0 的历史数据没有改写。
